# Design

## Context

See proposal.md Why. Current state: the string "Oyster" is hardcoded in 6 source locations — `web/src/App.tsx` (header brand link, login hero), `web/index.html` (`<title>`), `src/app.ts` (OpenAPI info title + two no-UI fallback HTML pages), `README.md`, plus build output `public/` (regenerated by `vite build`). Technical identifiers reuse the `oyster-` prefix: session cookie `oyster_session` (`src/auth/session.ts`), localStorage keys `oyster-theme`/`oyster-mode` (`web/src/theme/registry.ts` and inline boot script in `web/index.html`), npm name `oyster-foundation`. No spec pins the product name.

## Goals / Non-Goals

**Goals:**
- One consistent user-visible name "In my Belly" at every entry point (tab title, header, login, API docs, fallbacks, README).
- Zero behavior change: same routes, auth, storage, themes, tests.

**Non-Goals:**
- No rename of cookie, storage keys, npm name, repo dir, image, or homelab URLs (breaking, excluded per proposal).
- No logo, icon, theme, or copy redesign beyond the name swap.

## Decisions

- **Visible-strings-only rename (over full identifier rename).** Rationale: renaming `oyster_session` logs out every user and renaming storage keys drops saved theme/mode; cost with no user benefit. Alternative (full rename with migration/dual-read) rejected as disproportionate for a branding change.
- **Direct string replacement at each site (over a shared brand constant).** Rationale: only ~6 sites, each in a different layer (React, static HTML, Fastify, docs); a shared constant would cross the client/server boundary for no reuse benefit. Alternative (e.g. `APP_NAME` constant + import) considered; acceptable only if implementer finds further occurrences warranting it.
- **`public/` regenerated by build, not hand-edited.** Rationale: `web/vite.config.ts` builds into `../public` with `emptyOutDir`; hand edits are overwritten. Implementation rebuilds (or verifies CI rebuilds) so the served bundle title matches.
- **Title form "In my Belly — Places".** Keeps the existing `— Places` suffix pattern from `web/index.html`, only swapping the brand prefix.

## Risks / Trade-offs

- [Stale served bundle] `public/` is checked in and served by Fastify static — if the implementer edits `web/` but does not rebuild, users still see "Oyster" → Mitigation: rebuild web and assert no "Oyster" in `public/index.html` (bundle JS chunk names change; assert on HTML + source, not hashed JS).
- [Missed occurrence] grep for `Oyster`/`oyster` may surface docs/skill references (`skills/ops/SKILL.md`, `.env.sample` homelab URL) that must NOT change → Mitigation: change only user-visible product strings; leave URLs, cookie, storage keys, and ops docs intact; final grep review classifies each hit.
- [Test brittleness] any test asserting "Oyster" text fails after rename → Mitigation: update assertions to "In my Belly"; no test-logic change.

## Migration Plan

1. Deploy as a normal release; no data migration, no env changes.
2. Rollback: revert strings; no state to unwind (identifiers unchanged, sessions and preferences survive both directions).
